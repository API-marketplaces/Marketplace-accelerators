# MonetizeMate Questionnaire Feature - Technical Document

## 1. Purpose

The questionnaire feature collects business context from a user and converts it into API monetization strategy recommendations. In the current implementation, the questionnaire is adaptive: each next question is generated by an LLM based on the selected industry and previous answers.

The output is not only a list of monetization models. The backend asks the LLM to return a complete strategy package containing:

- Ranked monetization recommendations
- Pricing tiers
- Packaging strategy
- Implementation roadmap

## 2. Main User Flow

```text
User selects industry
        |
        v
Frontend opens questionnaire page
        |
        v
Frontend requests next question
        |
        v
Backend asks Groq LLM for one adaptive MCQ
        |
        v
User answers or skips question
        |
        v
Frontend sends full conversation again
        |
        v
Backend generates next question or marks completed
        |
        v
Frontend sends all answers for recommendation analysis
        |
        v
Backend asks Groq LLM for monetization strategy JSON
        |
        v
Frontend stores result in sessionStorage
        |
        v
User is redirected to recommendation page
```

## 4. Frontend Flow

### 4.1 Entry Point

The user starts from the Strategy Adviser page and selects an industry. The app navigates to:

```text
/dashboard/strategy-adviser/questionnaire?industry=<selectedIndustry>
```

The questionnaire page reads the industry from the URL:

```typescript
const selectedIndustry = searchParams.get('industry') || '';
```

If the user is not authenticated, the page redirects to `/login`. If no industry is selected, it redirects back to `/dashboard/strategy-adviser`.

### 4.2 State Managed by the Questionnaire Page

The page keeps the questionnaire state in React state:

```typescript
const [flowType, setFlowType] = useState<FlowType>('loading');
const [history, setHistory] = useState<ConversationEntry[]>([]);
const [currentQuestion, setCurrentQuestion] = useState<GeneratedQuestion | null>(null);
const [currentAnswer, setCurrentAnswer] = useState('');
const [error, setError] = useState<string | null>(null);
```

Important state fields:

- `history`: list of answered or skipped questions.
- `currentQuestion`: question currently shown to the user.
- `currentAnswer`: selected answer for the current question.
- `flowType`: controls UI mode such as loading, thinking, question, analyzing, or generating.

### 4.3 Requesting the Next Question

The frontend calls:

```text
POST /api/questionnaire/next
```

This is a Next.js API route. It forwards the request to FastAPI:

```text
POST /api/v1/questionnaire/next
```

Payload shape:

```json
{
  "industry": "SaaS",
  "question_number": 2,
  "conversation": [
    {
      "question_id": "q1",
      "question": "What stage is your API product currently in?",
      "answer": "Already live with paying customers"
    }
  ]
}
```

The frontend sends the full conversation each time so the backend can generate the next question contextually.

### 4.4 Answer, Skip, and Previous

When the user clicks Next:

```typescript
const updatedHistory = [...history, { question: currentQuestion, answer: currentAnswer }];
setHistory(updatedHistory);
fetchNextQuestion(updatedHistory);
```

When the user skips:

```typescript
const updatedHistory = [...history, { question: currentQuestion, answer: 'Skipped by user' }];
```

The backend detects `"Skipped by user"` and instructs the LLM not to repeat the same question or a close variant.

When the user goes back:

- Last item is removed from `history`
- Previous question is restored as `currentQuestion`
- Previous answer is restored as `currentAnswer`

### 4.5 Completion

When the backend returns:

```json
{
  "completed": true,
  "question": null
}
```

the frontend calls `analyzeAnswers(conversation)`.

Then it sends:

```text
POST /api/monetization/recommend-llm
```

which proxies to:

```text
POST /api/v1/monetization/recommend/llm
```

The recommendation result is stored in:

```typescript
sessionStorage.setItem('recommendations_data', JSON.stringify(data));
```

Then the user is redirected to:

```text
/dashboard/recommendation?analysisSource=questionnaire-llm&selectedIndustry=<industry>
```

## 5. Backend Adaptive Question Generation

### 5.1 Endpoint

Defined in:

```text
MonetizeMate-Backend/app/api/monetization_recommendation_endpoints.py
```

Endpoint:

```text
POST /api/v1/questionnaire/next
```

Request model:

```python
class NextQuestionRequest(BaseModel):
    industry: str
    question_number: int
    conversation: List[AnsweredQuestion] = []
```

Each previous answer uses:

```python
class AnsweredQuestion(BaseModel):
    question_id: str
    question: str
    answer: str
```

### 5.2 Completion Boundary

The backend uses the number of answered questions:

```python
total_answered = len(request.conversation)
```

Hard rule:

```python
if total_answered >= 15:
    return {"completed": True, "question": None}
```

The LLM is also instructed that:

- Below 10 questions, completion must always be false.
- After 10 or more questions, completion can be true only if enough signal exists.

So the practical range is usually 10 to 15 questions.

### 5.3 Questionnaire Phases

The backend guides the LLM through phases using `_questionnaire_phase(total_answered)`.

| Answer Count | Phase | Focus |
|---|---|---|
| 0-2 | Foundations | Business/product stage, API existence, target customer, monetization goal |
| 3-6 | Customer & Value | Customer segment, value proposition, acquisition channel, competition |
| 7-10 | Monetization Specifics | Willingness to pay, revenue model, pricing sensitivity, revenue goals |
| 11+ | Readiness & Scale | Metering, billing, compliance, team resources, launch timeline, expansion |

This prevents the system from asking advanced pricing or billing questions before it knows whether the user even has an API/product.

### 5.4 LLM Call

The backend calls Groq through:

```python
call_groq_sync(messages, model=STRATEGY_CHAT_MODEL, max_tokens=800, json_mode=True)
```

Groq endpoint:

```python
GROQ_URL = "https://api.groq.com/openai/v1/chat/completions"
```

Model:

```python
STRATEGY_CHAT_MODEL = "openai/gpt-oss-120b"
```

The API key comes from:

```python
settings.GROQ_API_KEY
```

### 5.5 Expected LLM Output for Next Question

The backend asks for this JSON:

```json
{
  "completed": false,
  "question": {
    "id": "q3",
    "title": "Your specific question here?",
    "description": "One sentence explaining why this matters for monetization strategy",
    "options": [
      { "label": "Option text A", "value": "Option text A" },
      { "label": "Option text B", "value": "Option text B" },
      { "label": "Option text C", "value": "Option text C" },
      { "label": "Option text D", "value": "Option text D" }
    ]
  }
}
```

Or, when finished:

```json
{
  "completed": true,
  "question": null
}
```

### 5.6 JSON Parsing and Normalization

LLM responses can contain malformed JSON or markdown fences, so the backend uses:

```python
_extract_json_object(response_text)
```

This function:

- Removes markdown fences such as ```json
- Finds the first `{`
- Tries normal `json.loads`
- Trims to the last closing brace if needed
- Attempts `_repair_json` for truncated JSON

After parsing, the backend normalizes the question:

- Ensures `id` exists
- Ensures `title` exists
- Ensures `description` exists
- Ensures options are a list
- Falls back to default Likert options if options are missing or invalid
- Limits options to maximum 5

## 6. Backend Recommendation Generation

### 6.1 Endpoint

Endpoint:

```text
POST /api/v1/monetization/recommend/llm
```

Request model:

```python
class AnalyzeQuestionnaireRequest(BaseModel):
    industry: str
    answers: List[AnsweredQuestion]
```

### 6.2 Prompt Construction

The endpoint converts answers to text:

```python
answer_lines = "\n".join(
    f"- {answer.question}: {answer.answer}"
    for answer in request.answers
)
```

Then it calls:

```python
messages = build_monetization_strategy_messages(request.industry, answer_lines)
```

The prompt template lives in:

```text
MonetizeMate-Backend/app/core/prompt_templates.py
```

The prompt forces a stable JSON shape with these top-level fields:

- `analysisSource`
- `selectedIndustry`
- `primaryRecommendation`
- `recommendations`
- `pricing`
- `packaging`
- `roadmap`

### 6.3 Recommendation LLM Call

The backend calls:

```python
call_groq_sync(
    messages,
    model=STRATEGY_CHAT_MODEL,
    max_tokens=6500,
    json_mode=True,
    temperature=0.35
)
```

Lower temperature is used here so strategy output remains more consistent and structured.

### 6.4 Recommendation Normalization

After parsing the LLM response, the backend normalizes different sections:

```python
result = _normalize_recommendations(payload, request.industry)
result["pricing"] = _normalize_pricing(payload)
result["packaging"] = _normalize_packaging(payload)
result["roadmap"] = _normalize_roadmap(payload)
```

Normalization protects the frontend from incomplete or inconsistent LLM output.

For recommendations, the backend ensures each item has:

- `id`
- `name`
- `description`
- `score`
- `reasoning`
- `implementation`
- `implementationSteps`
- `timeline`
- `revenueImpact`
- `pros`
- `cons`
- `risks`
- `mitigations`
- `successMetrics`
- `icon`
- `color`
- `bgColor`

For missing pricing, packaging, or roadmap, default fallback structures are returned.

### 6.5 Activity Logging

After recommendations are generated, the backend logs the activity:

```python
log_recommendation_activity(
    db,
    current_user,
    request.industry,
    request.answers,
    result.get("recommendations", [])
)
```

This is useful for admin/audit visibility.

## 7. Authentication Flow

The frontend does not call FastAPI directly from the browser for these actions. It calls Next.js API routes first.

Next.js reads the JWT cookie:

```typescript
const COOKIE = process.env.JWT_COOKIE_NAME || 'session'
const sessionCookie = cookieStore.get(COOKIE)
```

If the cookie is missing, it returns:

```json
{ "message": "Authentication required" }
```

If present, it forwards the request to FastAPI with:

```text
Authorization: Bearer <session-token>
```

The recommendation endpoint uses:

```python
current_user: AudienceResponse = Depends(get_current_user)
```

## 8. Static Questionnaire CRUD Layer

There is also a database-backed questionnaire API:

```text
POST /api/v1/questionnaire/
GET  /api/v1/questionnaire/
```

This is implemented in:

```text
MonetizeMate-Backend/app/api/questionnaire_endpoints.py
```

It uses the `questionnaire` table:

```python
class Questionnaire(Base):
    __tablename__ = "questionnaire"
    id = Column(Integer, primary_key=True, index=True)
    question = Column(Text, nullable=False)
    answer_type = Column(String, nullable=False)
    options = Column(Text, nullable=True)
    category = Column(String, nullable=True)
    description = Column(Text, nullable=True)
```

This static CRUD path is separate from the current adaptive LLM questionnaire. It can store reusable questions, but the active frontend questionnaire flow currently requests adaptive questions from `/questionnaire/next`.

## 9. Legacy Rule-Based Recommendation Path

The backend still contains an older rule-based endpoint:

```text
POST /api/v1/monetization/recommend
```

It expects:

```json
{
  "answers": {
    "1": "Agree",
    "2": "Strongly Agree"
  }
}
```

It fetches stored `Questionnaire` records from the database and scores predefined monetization models using keyword checks in question text.

Example:

- If question text contains `"user base"` and answer is `"Agree"` or `"Strongly Agree"`, it increases `subscription` and `hybrid`.
- If question text contains `"revenue"`, it increases `value-based`.
- If question text contains `"competition"`, it increases `freemium`.

This path is simpler and deterministic, but it is not the main LLM-based questionnaire flow used by the current frontend page.

## 10. Error Handling

Important error paths:

- Missing `GROQ_API_KEY`: backend returns `500`.
- Groq rate limit: backend retries and can return `429`.
- Groq timeout: backend retries and can return `502`.
- Invalid LLM JSON: backend attempts repair, otherwise returns `502`.
- Missing frontend session cookie: Next.js API route returns `401`.
- Failed recommendation generation: frontend displays an error and allows retry.

## 11. Current Technical Characteristics

- Questions are generated dynamically, not hardcoded in the current flow.
- Conversation history is stored in frontend memory during the questionnaire session.
- Final recommendation result is stored in browser `sessionStorage`.
- Backend normalizes LLM output before returning it.
- Recommendation generation is authenticated.
- The question generation endpoint is proxied with authentication headers by Next.js.
- The LLM prompt is centralized so the recommendation JSON shape stays consistent.
